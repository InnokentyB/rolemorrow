## Path to an application others can use

1. Owner UAT and semantic evaluation: shortlist usefulness, false-supported requirements, missed country/salary constraints and understandable uncertainty.
2. Shared-service boundary: authentication, account/file authorization, per-user storage isolation and isolated demo sessions.
3. Operations: durable database/job queue, budgets/rate limits, observability without private content, recovery tests and release rollback.
4. Mail: choose/verify domain; configure sender authentication and inbound adapter; test delivery/receive/replay/bounce handling using owner-controlled addresses. Sending remains explicit and confirmed; no mass applications.
5. Application submission: employer-specific browser/API integrations with visible review, CAPTCHA/login handoff and evidence of accepted submission. A prepared packet or delivered email is not proof of ATS acceptance.
6. Data lifecycle: consent, retention/export/deletion across backups/providers, encrypted storage and file scanning before broader document use.
